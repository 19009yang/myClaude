# LaMemory 架构与实施方案

日期：2026-11-09

**Layered Aggregated Memory（简称 LaMemory）** 是 myClaude 计划开发的分层聚合记忆系统。本文描述目标架构、现有代码缺口和实施边界，配套执行步骤见 [LaMemory 开发指南](lamemory-development-guide.md)。

M0–M3 的单机运行时已实现，`core/memory.py` 作为 `core/lamemory/` 的兼容门面。当前采用关键词模式；M2/M3 已完成离线功能验证与 DeepSeek 在线交付 smoke，系统效果评估与完整对照评测仍待实施。启用方式和验收限制见 [使用与验证](lamemory-usage.md) 与 [M2/M3 开发交付](lamemory-m2-m3.md)。

## 1. 目标

LaMemory 要支持跨会话记忆，并能解释一条记忆的来源、当前有效性和本次被使用的原因。

系统围绕三类操作建立闭环：

- 记录：保留原始消息，提取事实、偏好和事件。
- 使用：按当前请求检索，在上下文预算内选择相关信息。
- 维护：处理更正、遗忘和重复，刷新聚合摘要，记录失败与重试。

目标运行环境是单机 Python 应用。先使用 SQLite 和可替换模型接口，实现可测试的最小版本；达到明确需求后再增加复杂能力。

## 2. 分层聚合模型

```text
原始消息 ──提取──> 结构化记忆 ──按主题聚合──> 主题摘要
                     │                         │
                     └──────稳定信息聚合────────┘
                                  ↓
                              用户概览

任务结果与反馈 ──验证──> 经验记录

当前请求 ──检索与预算选择──> 工作上下文 ──> 模型回复
```

| 组成 | 职责 | 维护要求 |
|---|---|---|
| 原始消息 | 对话与工具交互的证据 | 保留来源和顺序，不因工作上下文压缩而丢失 |
| 结构化记忆 | 独立事实、偏好和事件 | 保存类型、作用范围、事件时间、状态和版本 |
| 主题摘要 | 按项目或主题聚合记录 | 保存来源 ID 与源版本，来源变更时失效 |
| 用户概览 | 小体积稳定偏好与背景导航 | 避免堆入所有历史细节，限制预算 |
| 经验记录 | 有适用条件的可复用做法 | 经过反馈验证，支持撤销和版本替代 |
| 工作上下文 | 当前会话的有限输入视图 | 保持消息关系合法，不替代持久化证据 |

“层”表达信息粒度与聚合关系。结构化记录依然能够直接检索，摘要不会成为查找证据的唯一入口。经验记录是另一类可检索知识，不强制经过用户概览聚合。

## 3. 当前实现与缺口

改造前的 `core/memory.py` 支持 JSONL 历史恢复、模型提取长期条目、Markdown 注入和会话摘要压缩。下表记录本次改造的起点；聊天流程继续通过 `add_message()`、`build_context()` 兼容入口使用新服务。

| 当前情况 | LaMemory 的改进目标 |
|---|---|
| 固定文件路径且含反斜杠，`memory_path` 参数未参与路径选择 | 使用明确路径配置，隔离用户与会话 |
| 长期条目追加到 Markdown | 结构化记录、来源关联和存储约束 |
| 每次注入整份长期记忆 | 按需检索、主题加载和输入预算 |
| 去重依赖提示词要求 | 幂等写入、精确去重和来源合并 |
| 更正信息没有独立版本关系 | 新记录替代旧记录，保留历史证据 |
| 压缩时数组与字符串处理不一致 | 校验结果后提交，不破坏原始历史 |
| 提取是否执行依赖正数 usage | 用完整轮次事件驱动，usage 单独计量 |
| 提取失败可能传播到主对话 | 持久化任务、有限重试和明确失败状态 |

这些改动首先通过回归用例约束，再逐步接入新的存储与服务。

## 4. 模块与接口

新模块统一放在 `core/lamemory/`，`core/memory.py` 保留兼容门面。

```text
聊天流程 / 主动记忆工具
          ↓
    LaMemoryService
          ↓
提取 / 冲突处理 / 检索 / 上下文 / 聚合 / 任务处理
          ↓
    SQLite Store + Model Providers
```

`LaMemoryService` 绑定可信的用户与会话身份，提供消息追加、轮次提交、主动保存、查询、更正、遗忘、检查、上下文构建和任务等待等操作。

新主动工具统一使用 `lamemory_` 前缀：`lamemory_store`、`lamemory_search`、`lamemory_update`、`lamemory_forget`。模型不能通过工具参数切换到任意用户身份。

存储表使用 `lamemory_` 前缀。提取结果必须校验后落库；索引可从有效记录重建。模型配置通过 provider 实例传入，测试使用 fake provider，避免读取真实会话或调用付费模型。

## 5. 一致性与更新

- 同一轮次重复提交只产生一个提取任务。
- 相同事实可以补充多个来源，不因普通重复提及无限增长。
- 事件时间与记录时间分开；不确定的发生时间保持为空。
- 对当前事实的明确更正创建替代关系，默认检索只使用有效版本。
- 遗忘一条记忆后，旧来源重放不能使它自动恢复。
- 来源失效使关联摘要变脏；重建前不继续注入包含旧内容的摘要。
- 模型调用在写事务之外进行，校验完成后短事务提交。
- 提取失败仍保留原文和任务；保存失败不能向用户报告成功。

## 6. 开发阶段

| 阶段 | 交付内容 | 验收重点 |
|---|---|---|
| M0 | 当前路径、隔离、压缩和失败处理修复 | 现有聊天稳定，测试与真实数据分离 |
| M1 | 结构化记录、来源、提取、检索、更新/遗忘和预算 | 新会话正确召回、用户不串数据、失败可恢复 |
| M2 | 主题摘要、用户概览和增量整理 | 来源变更可传播，摘要不过期使用 |
| M3 | 经验候选、验证和晋升 | 已验证经验能帮助新任务，错误经验可撤销 |

M1 可先启用关键词模式；真实语义检索必须接入可用 embedding，并记录模型版本与维度。复杂聚类、多进程任务和跨机器部署留待后续需求驱动。

## 7. 验证与评测

开发测试覆盖跨会话召回、用户/会话隔离、重复提交、更正、时间检索、遗忘、来源追溯、超预算、工具消息完整性、模型故障和迁移重放。

项目内建立 `benchmarks/lamemory/` 作为计划中的评测目录，使用明确的任务清单、初始化消息和评分规则。初始覆盖依赖记忆、部分依赖、不适用和通用任务，独立统计不同类型结果。

对照组只使用同一 myClaude Agent：关闭长期记忆、现有 Markdown 算法、LaMemory。模型、工具、预算、原始初始化数据和评分方式保持一致，每个独立任务从冻结快照启动。

报告任务得分、通过率、轮数、时间、错误率、检索指标及全部模型用量。提取与摘要成本单独统计，建库成本与在线成本分别呈现。经验学习另设训练/测试划分，不能用测试答案训练后续测试任务。

当前关键词模式引擎的 M0–M3 已通过离线回归，原有 fake 聊天 smoke 已重跑通过；此前 DeepSeek `deepseek-flash` 的真实记忆 smoke 覆盖 M0/M1。2026-11-10 补充的 DeepSeek 在线交付 smoke 通过 M2 9 项、M3 15 项检查，包含真实摘要、经验候选和实际执行反馈闭环。测试记录位于 `benchmarks/lamemory/` 和 `benchmarks/providers/`；合成场景的在线功能验证不代表系统摘要质量或复杂任务迁移收益，尚未取得 LaMemory 正式对照评测分数。
