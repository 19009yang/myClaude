## M2/M3 在线验证

```bash
# 读取项目 .env 中的 DeepSeek 配置；output 必须是尚不存在的新路径
uv run python -m benchmarks.lamemory.live_m2_m3 --output /tmp/lamemory-m2-m3-live-new.json
```

验证入口为 [live_m2_m3.py](live_m2_m3.py)，使用两个临时数据库及合成消息，运行结束后清理数据库。不会读取真实会话；不会覆盖历史报告。仅启用确定性的整数排序去重工具与绑定身份的记忆工具，不执行模型生成的 shell 命令。

| 范围 | 实际验证内容 |
|---|---|
| M2：9 项检查 | 真实用户概览与项目摘要、来源版本、跨会话回答、用户/项目隔离、更正后的脏摘要排除及版本重建、新值回答、遗忘即时生效、遗忘后重建保留原文 |
| M3：15 项检查 | 真实工具训练轨迹、幂等提取、真实候选及适用性、候选不召回、训练重放不计数、两组不同输入的实际执行与反馈去重/晋升、跨会话实际执行及经验注入、用户隔离、显式撤销及重新连接后的持久化 |

M2 的记忆由可信宿主带原文来源保存，再交给真实模型聚合。模型生成的项目端口摘要从 `43127` 正确更新为 `52941`，跨会话回答同步更新；遗忘后该主题变为空，原始来源仍保留。

M3 的候选由真实模型从 `sort_unique` 工具调用轨迹提取，未使用手写候选替代。宿主把候选步骤提供给两个独立验证轮次，使用不同整数列表实际执行工具，并核对工具输出和最终 JSON 是否等于 `sorted(set(input))`。通过后提交 `evidence_kind=test`，成功数达到 2 才晋升；训练轨迹重放保持成功数为 0。晋升后新会话实际执行并注入经验，随后由测试宿主显式撤销。这里验证的是同类简单任务的闭环，不能推导复杂任务收益或广泛迁移能力，也未在线覆盖错误反馈撤销和版本替代分支。

报告保留模型标识、脱敏端点、配置哈希、源码哈希、每次模型请求/响应、分项检查、消息来源、任务状态、真实工具执行记录及用量。总用量按原始模型响应统计一次；`memory_usage_events` 是用途分类视图，不应再次累加。未保存 API key。

首次在沙箱内运行因网络连接限制失败（7 次尝试、0 个成功响应、0 个已记录 tokens），证据保留于 [首次失败报告](results/m2-m3-live-attempt-1.json)；获准联网后完成上表在线验证。同期离线回归重跑为 **69 项 LaMemory 测试、20 项 provider 测试通过**；LaMemory 的 3 项 HTTP 测试在沙箱内因禁止绑定端口未能执行，获准使用回环地址后全量通过。原有 58 项交付报告继续保留。

## 原有离线与 M0/M1 验证

离线用例使用临时库和 fake provider，覆盖来源复用、轮次提交幂等、事件时间、用户/会话隔离、版本更正、待裁决冲突、遗忘与旧来源重放、摘要校验、预算和工具链完整性、提取故障重试、重启恢复、SQLite 外键与批次回滚、只读迁移与重复导入。fake 的零 token 用量不代表真实模型成本。

M2/M3 新增 24 项行为用例，覆盖 M1 库升级保留消息/来源/任务、项目隔离、手动成员随版本传播、来源增补、概览过滤及导航、摘要生成期间更正、摘要故障重试/重启、flush 等待新生成的摘要、精确整理与大量来源的预算导航；以及经验候选、独立反馈、自评过滤、轨迹重放、用户认可、失败撤销、版本替代、批次回滚、自动候选投递与 CLI 完整闭环。本次记录包含实际测试输出、源码哈希及现有 fake smoke 的重跑结果；未改写历史 fake/real smoke 报告。接口和限制见 [M2/M3 开发交付](../../docs/lamemory-m2-m3.md)。

`smoke.py` 使用不依赖终端输入的 `ChatRunner`，所有状态保存在临时库，执行后删除。报告保存配置、配置哈希、检索模式、命中来源、分项检查、耗时及分用途模型 usage；真实模式不输出密钥。ChatRunner 默认仅启用绑定的记忆工具，宿主可显式增加普通工具；内置安全确认在无人值守模式返回未执行。聊天轮数和模型请求有界，宿主添加的同步工具需要自行遵守超时；此 runner 不提供操作系统级工作区隔离。
